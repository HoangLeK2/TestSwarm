# Active Plans

Status: active
Last audited: 2026-05-25

This directory tracks implementation gaps and follow-up plans that are not yet
module contracts. Use these files when assigning work to agents or developers.

Rules:

- Keep product intent in `docs/product/`.
- Keep durable implementation contracts in `docs/modules/`.
- Keep active gap/action tracking here.
- Keep historical plans in `docs/archive/plans/`.
- When a gap is resolved, update the relevant module/profile docs and either
  remove the gap or mark it done with the resolving change.

## Active Plan Files

| Plan | Purpose |
|---|---|
| `core-release-plan.md` | Core release scope, module acceptance gates, ticket slices, and rollout sequence |
| `core-release-qc-process.md` | QC process, UAT matrix, smoke/regression checks, go/no-go, and rollback verification for the core release |
| `core-release-scope-validation.md` | Scope-to-code validation, automated smoke results, blockers, and minimum fix tickets before acceptance |
| `social-platform-extension-gaps.md` | Known gaps for Facebook hardening and future TikTok/Instagram/Threads extensions |
| `flowgram-free-layout-workbench.md` | Phased delivery plan for a searchable, configurable, executable FlowGram workflow workbench |
